1. Enunciado y Objetivos de la Actividad

El objetivo de esta práctica es dominar la integración y el flujo de trabajo de Sass (SCSS) dentro del ecosistema moderno de desarrollo móvil y web con Ionic y Angular.

Requisitos especificados en el enunciado:
  1. Crear un proyecto Ionic - Angular (utilizando componentes Standalone).
  2. Trabajar sobre la página/componente ya generada llamada home.
  3. Permitir el uso de etiquetas HTML estándar y componentes de Ionic: título + botón + imagen.
  4. Título: en rojo, transformado a mayúsculas y centrado.
  5. Botón: alineado a la derecha y estilizado en color azul.
  6. Imagen: centrada en la pantalla con borde en color verde de grosor 3px.
  7. Aplicar todo el diseño mediante hojas de estilo Sass.
  8. Responder de forma argumentada a las preguntas técnicas planteadas:
    • ¿El componente usa Sass por defecto?
    • ¿Aplico Sass pero se compila solo? ¿Por qué con ionic serve no se ejecuta npm run watch:sass?

3. Implementación del Diseño con Sass Modular

Siguiendo la arquitectura profesional recomendada en el Patrón 7-1 (visto en las sesiones teóricas previas patron-7-1-demo y m9-3-sass-fundamentals), se ha estructurado una capa de abstracciones dentro de src/theme/abstracts/ que contiene las variables y los mixins del sistema de diseño, importados mediante la directiva moderna @use de Dart Sass.

3.1. Definición de Tokens y Variables (_variables.scss)

Se centralizan todos los valores requeridos en el enunciado para asegurar un código mantenible y desacoplado: 

// src/theme/abstracts/_variables.scss

// Requisito 1: Título en rojo, mayúsculas y centrado
$title-color: #d32f2f;
$title-transform: uppercase;
$title-align: center;

// Requisito 2: Botón en azul alineado a la derecha
$button-bg: #1976d2;
$button-bg-hover: #1565c0;
$button-text-color: #ffffff;
$button-radius: 8px;

// Requisito 3: Imagen con borde verde de 3px
$img-border-width: 3px;
$img-border-style: solid;
$img-border-color: #2e7d32;
$img-border-radius: 12px;

3.2. Mixins de Maquetación y Bordes (_mixins.scss)

// src/theme/abstracts/_mixins.scss
@use 'variables' as v;

@mixin flex-center {
  display: flex;
  justify-content: center;
  align-items: center;
}

@mixin flex-align-right {
  display: flex;
  justify-content: flex-end;
  align-items: center;
}

@mixin framed-border($width: v.$img-border-width, $style: v.$img-border-style, $color: v.$img-border-color, $radius: v.$img-border-radius) {
  border: $width $style $color;
  border-radius: $radius;
  box-shadow: 0 6px 18px rgba(46, 125, 50, 0.2);
}

@mixin styled-button($bg: v.$button-bg, $hover-bg: v.$button-bg-hover, $text: v.$button-text-color) {
  background-color: $bg;
  color: $text;
  border: none;
  border-radius: v.$button-radius;
  padding: 12px 24px;
  font-weight: 600;
  cursor: pointer;
  transition: all 0.25s ease-in-out;
  &:hover {
    background-color: $hover-bg;
    transform: translateY(-2px);
  }
}

3.3. Estilos del Componente Home (home.page.scss)

En home.page.scss se aplican los tres requerimientos usando anidamiento jerárquico (nesting), llamadas a mixins con @include y selectores contextuales: 

@use '../../theme/abstracts/variables' as v;
@use '../../theme/abstracts/mixins' as m;

.page-container {
  // Requisito 1: Título en rojo, mayúsculas y centrado
  .assignment-header .assignment-title {
    color: v.$title-color;
    text-transform: v.$title-transform;
    text-align: v.$title-align;
    font-size: 2rem;
    font-weight: 800;
  }

  // Requisito 2: Botón a la derecha en azul
  .button-section {
    @include m.flex-align-right;
    .btn-sass-html {
      @include m.styled-button(v.$button-bg, v.$button-bg-hover, v.$button-text-color);
    }
    .btn-sass-ionic {
      --background: #{v.$button-bg};
      --color: #{v.$button-text-color};
    }
  }

  // Requisito 3: Imagen centrada con borde verde de 3px
  .image-section .image-center-container {
    @include m.flex-center;
    .framed-banner-img {
      display: block;
      margin: 0 auto;
      @include m.framed-border;
    }
  }
}

4. Respuestas Argumentadas a las Preguntas Planteadas

Pregunta 1: ¿El componente usa Sass por defecto?

Respuesta directa: SÍ, Ionic con Angular utiliza Sass (SCSS) por defecto en todos sus componentes y páginas.

Fundamentación técnica:

  1. Configuración en angular.json: Al generar un proyecto Ionic Angular, el archivo de configuración global define explícitamente que los generadores de código (schematics) creen componentes y páginas con extensión scss: 
    "schematics": {
  "@ionic/angular-toolkit:page": {
    "styleext": "scss",
    "standalone": true
  }
},
"inlineStyleLanguage": "scss",
"styles": ["src/global.scss", "src/theme/variables.scss"]
  2. Enlace en el decorador @Component: El componente inicial src/app/home/home.page.ts declara: 
    @Component({
  selector: 'app-home',
  templateUrl: 'home.page.html',
  styleUrls: ['home.page.scss']
})
    Ionic adopta de forma predeterminada la sintaxis .scss (Sassy CSS) frente al CSS clásico o Sass indentado antiguo (.sass).
  3. Ecosistema global de temas: Toda la arquitectura de theming de Ionic Framework (src/theme/variables.scss y src/global.scss) está diseñada nativamente en Sass, permitiendo sobreescribir CSS Custom Properties y variables SCSS de manera unificada.

Pregunta 2: ¿Aplico Sass pero se compila solo? ¿Por qué no hacemos npm run watch:sass?

Respuesta directa: SÍ, Sass se compila automáticamente y en memoria al ejecutar ionic serve. No es necesario ni aplicable ejecutar npm run watch:sass.

Fundamentación técnica y comparativa de flujos de trabajo:

Aspecto Proyectos Web Planos (p. ej. m9-3-sass-fundamentals) Proyectos Ionic - Angular (ionic serve)
Pipeline de construcción Inexistente. No hay empaquetador (Webpack, Vite o esbuild). Integrado mediante @angular/build:application (con motor Vite + esbuild).
Compilador de Sass Debe instalarse manualmente en devDependencies (paquete sass). Viene integrado y gestionado internamente por el Angular CLI.
Modo de escucha (Watch) Requiere un script en package.json: "watch:sass": "sass --watch scss:dist/css". Automático e inherente al comando ionic serve (que delega en ng serve).
Destino de la compilación Escribe archivos físicos .css y .css.map en la carpeta dist/css en disco. Compilación en memoria virtual (Virtual File System / RAM), optimizando I/O de disco.
Recarga de estilos Requiere recargar manualmente el navegador o usar extensiones como Live Server. Aplica Hot Module Replacement (HMR) instantáneo; los estilos se actualizan al guardar sin perder el estado de la aplicación.
Conclusión técnica: En Ionic con Angular, el desarrollador solo se enfoca en escribir su código en archivos .scss. El proceso de compilación, resolución de rutas, vendor-prefixing, optimización y refresco en el navegador corre de forma transparente y automática dentro del ciclo de vida de ionic serve.

5.2. Componente TypeScript (src/app/home/home.page.ts)

import { Component } from '@angular/core';
import {
  IonHeader, IonToolbar, IonTitle, IonContent,
  IonButton, IonCard, IonCardHeader, IonCardTitle,
  IonCardSubtitle, IonCardContent
} from '@ionic/angular';

@Component({
  selector: 'app-home',
  templateUrl: 'home.page.html',
  styleUrls: ['home.page.scss'],
  imports: [
    IonHeader, IonToolbar, IonTitle, IonContent,
    IonButton, IonCard, IonCardHeader, IonCardTitle,
    IonCardSubtitle, IonCardContent
  ],
})
export class HomePage {
  buttonClickMessage = '';

  onButtonClick(source: string) {
    this.buttonClickMessage = `¡Acción ejecutada desde el botón (${source}) con estilo azul Sass!`;
  }
}
